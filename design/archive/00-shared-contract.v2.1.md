# Automation Coach: shared design contract v2

Single source of truth for every file in `design/`. v2 supersedes `design/archive/00-shared-contract.v1.md` and folds in the owner's rulings of 2026-10-25 and the two consistency reviews (`design/99a-data-contract-review.md`, `design/99b-decision-consistency-review.md`; finding ids F-nn and DC-nn below refer to them). If a file conflicts with this one, this one wins; flag the conflict at the top of your output. Today is 2026-10-25.

## 1. Product and thesis
A coach that walks employees through deciding whether and how to automate a process, then recommends the best tool for each step. Ships as a standalone Windows download and integrates with **AutoMate** (WinUI 3 / C#, local, deterministic, **no AI at runtime**; AutomationId selectors; no coordinates; no confidence scoring for element resolution; fail loud). Never describe AutoMate itself as AI-powered; Coach is an optional design-time assistant.

**The model talks; the engine decides.** The recommendation path (classification, ladder choice, ROI math, environment fit, policy gating, exports, approvals) is a deterministic, auditable rules engine with no LLM in it. No LLM output, including an LLM judge, can change a verdict, rung, ROI figure, policy gate or approval. The model may write structured step data only as a **proposal the user confirms value by value**; the engine consumes nothing the user has not confirmed (applies in lite mode too).

## 2. Locked decisions (owner)
1. Coach core is a standalone library (engine, blueprint, catalog, connections, policy); AutoMate is the first "automation target" adapter; the standalone app is another shell.
2. Coach acts inside AutoMate: draft-only, user sees a diff, a single-use host-minted token from a trusted UI click approves apply/run, test runs are attended-only at first, every action maps to a Blueprint step. Nothing sends, deletes or runs without a human click. The AutoMate team owns the adapter API (draft import, diff, IPC); a file-based draft import is the fallback.
3. **Connections** (one abstraction): `managed` (customer pays platform subscription plus usage at cost + transaction fee; app to our gateway to OpenRouter), `byok_openrouter` and `byok_provider` (customer's key, called **direct from the client**, key in Credential Manager/DPAPI, never in logs, transcripts, blueprints, exports; no usage fee), `custom_openai_compat` (Azure OpenAI, LiteLLM, vLLM, corporate gateways, with a server profile), `local` (free; loopback OpenAI-compatible: Ollama, LM Studio, Foundry Local [preview], llama.cpp; servers are never bundled; no embedded inference). Local support is a launch requirement. A native Anthropic adapter is v1.1. Glossary: `byok_openrouter` means the customer's own OpenRouter API key; it is unrelated to OpenRouter's "BYOK" product.
4. **Managed is generally available only after written permission from OpenRouter (or an equivalent direct provider agreement) is on file.** Until then it ships behind a flag; BYOK and local are unaffected (OpenRouter ToS s7 bars reselling API access).
5. **Gateway privacy wording:** the gateway **does not store** prompts or completions and persists metadata only (user, model, tokens, cost, time). Prompts transit gateway memory, OpenRouter and the model provider. Copy says "not stored by us", never "we never see it". Any future in-transit scan may read content in memory and must persist counts only (P2, owner-approved exception). Managed requests always force provider data-collection deny.
6. **Tiers:** Individual, Team, Enterprise. Free offer: 14-day trial of the full Individual plan plus a permanent free no-model wizard with export; no free managed credits.
7. **Admin and user controls at launch.** Every setting is `locked` | `default` | `user_choice`. Policy is a signed bundle (ES256 unless Ed25519 support is verified in the chosen KMS and .NET), cached with an offline grace period (default 14 days, then `no_llm`). Individual runs on a signed baseline bundle. Machine-level enrollment (registry key) ships at launch so "disable personal keys" and "org policy required" have a hard path on managed devices. Enforcement is server-side for `managed` and for approvals/retention/sharing of every synced Blueprint; client-side for direct and local connections; local-only Blueprints sit outside server enforcement and the product says so. An **org environment profile** constrains the rules engine. Single org bundle at v1 (`environment.profiles[].groupIds` is the only group-aware field; multi-group tiebreak: first profile in array order; reserve an optional `scope` field).
8. **Full blueprint backup/sync to our servers is a capability for every sensitivity class.** `restricted` Blueprints stay on the device by default, show "Local only, not backed up", and an admin or the owner may opt in with one click. Approval metadata (hash, status, signer) may sync for any class. Encryption server-managed (per-tenant KEK, per-revision DEK, AES-GCM with AAD); the envelope reserves `enc.mode`. Customer-managed keys and the Enterprise org key vault (scoped sub-key mode A only) are P2, after a security review; do not sign Enterprise contracts requiring CMK before it ships. Backup window of 35 days is stated in the DPA. One region at launch (field present). Transcripts stay local by default.
9. **Roles:** `admin`, `coe_reviewer`, `builder`, `viewer`. Admin sees Blueprint metadata plus audited break-glass content access; content is readable by the owner, explicit shares and CoE Reviewers once in review. CoE Reviewer = Builder plus review (Builder rights include AutoMate draft/apply); may not approve their own Blueprint; Admin cannot approve; only a CoE Reviewer sets `approved`. `tiers.md` section 2 is the authoritative permission matrix; `coach-tools.json` role rules are generated from it.
10. **Telemetry off everywhere** (client-reported usage is classified as audit data and the product says so). Team audit retention 365 days. Sign-in not required for local, BYOK and no-model use; account required for sync, managed and orgs; signed offline entitlement token with 30-day grace. Up to 3 devices per user. Cloud: Azure.
11. Accessibility: WCAG 2.2 AA with keyboard and screen-reader support for the shell and portal. English UI in v1 with locale-safe strings; model replies in the user's language, best effort.
12. First buyer: CoE lead. Competitors are not named on the site.

## 3. Stages, ladder, diagnostic
Stages: `triage`, `capture`, `decompose`, `classify`, `environment_fit`, `design`, `build_handoff`, `test_plan`, `deploy_monitor`. Triage verdicts: `automate`, `fix_process_first`, `dont_automate`.

**Ladder (array order = ladder order; first rung that fits wins):** `eliminate`, `builtin_feature`, `api_connector`, `script`, `ui_automation`, `parser_ocr_ml`, `llm_node`, `human_checkpoint`, `llm_agent` (discouraged: always carries a warning and a justification card; reached only where a human checkpoint is forbidden or unfit). The engine's search order, fixtures and the Blueprint enum all use this order (F-01).

Diagnostic inputs: input structure, output determined by rules, cost of error and reversibility, frequency and volume, API vs UI-only (`interfaceAvailability`: `api_available`, `file_exchange`, `ui_only`, `unknown`; steps whose systems are all `paper_or_phone` are exempt, no `none` value), attended vs unattended and credentials, data sensitivity, language understanding or judgment required, `operations` tags, plus the engine fields listed in `rules-engine.md`. Every tool-settable diagnostic field equals the schema's set (F-25).

## 4. Conventions (all JSON is camelCase)
- **Ids:** `toolId` `^[a-z][a-z0-9_]*\.[a-z0-9][a-z0-9_]*$` max 80; org tools `^org\.[a-z0-9][a-z0-9_]{0,59}$`; `slug` `^[a-z][a-z0-9_-]{1,62}$`; entity ids `bp_`, `stp_`, `exc_`, `dec_`, `tst_`, `exp_`, `aud_` + 26-char ULID; connection id `^[a-z0-9][a-z0-9_-]{0,63}$` (built-in `managed`). Both schemas define these identically (F-09, F-10).
- **Skill scale** everywhere (`skillLevel`, `builderSkill`, `prefs.skillLevel` default `basic`): `none`, `basic`, `intermediate`, `advanced`.
- **Policy three-state modes:** the refusal value is `forbidden` (never `disabled`). `user_choice` omits `value`; `locked` and `default` carry it.
- **Model keys:** `<namespace>/<id>`: managed and byok_openrouter use the OpenRouter id as is; byok_provider `<providerId>/<id>`; custom_openai_compat `custom/<id>`; local `local/<id>`.
- **Wire casing:** roles and labels are snake/lower case (`coe_reviewer`; `certified`, `works`, `experimental`, `uncertified`); display names are UI copy only.
- **Versions:** `Blueprint.schemaVersion` string `^1\.[0-9]+$` (readers preserve unknown properties, writers emit schema properties only); `Policy.schemaVersion` required integer; clients ignore unknown non-`x-` policy keys.
- **Lengths:** `flowRef` and `exportRecord.targetId` max 120 characters; override and decision reasons max 400 (policy `reasonMinChars` max 400).
- **Spend:** cap micros = round half up (USD x 1,000,000).

## 5. Canonical entities
- **Blueprint:** `id`, `schemaVersion`, `version` (client edit counter), `etag` (client-local content tag, not used for sync), `title`, `owner`, `orgId`, `kind` (`new|rescue`), `status` (`draft|in_review|approved|built|deployed|retired`), `sensitivity` (`public|internal|confidential|restricted`), `stage`, `triage{verdict, rationale, answers, conditions, warnings, ruleTrace, overrideDecisionId, provenance}` (derived props carry `x-derived`), `process{summary, trigger, frequency, volume, timePerRunMinutes, people[], provenance}`, `steps[]`, `exceptions[]`, `environmentProfileRef{id, policyVersion}`, `roi{}`, `decisions[]`, `tests[]`, `deployPlan{}`, `exports[]`, `auditLog[]`, `engine{}`, `sync{deviceId, baseRev, lastSyncedRev, lastSyncedAt, state}`, `createdAt`, `updatedAt`.
- **Step:** `id`, `order`, `name`, `description`, `actor`, `inputs[]`, `outputs[]`, `decisionPoints[]`, `exceptionRefs[]`, `diagnostic{...}`, `environment.systems[]` (tool-settable: `role, accessModes, accessEvidence` [host forces `claimed` on model writes]`, uiLocator.kind, authModel, profileSystemId`), `recommendation{rungId, toolId, rationale[], alternatives[]}` (engine-owned), `override{by, reason, at}` (and a matching `decisions[]` record), `llmJustification{whyNotCode, validator, fallback, costPerRun}`, `asBuilt`, `provenance` (Evidence), `createdBy`, `confirmationState`, `confirmedBy`, `confirmedAt`.
- **Exception:** `id`, `description`, `frequency`, `handling`, `provenance`, `createdBy`, `confirmationState`, `confirmedBy`, `confirmedAt`.
- **Provenance** (`diagnostic.provenance[field]`, `process.provenance[field]`, `triage.provenance[answer]`): `{origin: user_stated|coach_inferred|engine_derived, evidence?: Evidence}`; `Evidence`: `{source: user_turn|pasted_document, turnId, docId?, quote, at?}`. Risk facts need a verbatim typed user quote.
- **Override/decision reasons:** Blueprint floor 15 characters; `coach.override.reasonMinChars` minimum is 15; the tool floor is 1 and the host rejects shorter. `chosenToolId` is required when `chosenRungId` is not `eliminate`.
- **Test:** `id, title, kind (happy_path|exception|regression|attended_run|negative), stepIds[], exceptionIds[], given, when, then, exampleData (max 400), status (proposed|confirmed|passed|failed|skipped), lastRunAt, lastRunId, lastRunDetail, createdBy, provenance` (+ confirmation fields). `expected`/`lastResult` in older text mean `then` / (`status`, `lastRunAt`, `lastRunDetail`).
- **DeployPlan:** `{backupOwner, failureSignals[{stepId, signal, notify}], manualFallback, changeTriggers[], reviewAfterDays (7..365), createdBy, confirmationState, confirmedBy, confirmedAt}`. ROI tracking is manual entry at `reviewAfterDays`.
- **ExportRecord:** `id, kind (handoff_brief|process_document|review_packet|blueprint_json|automate_flow_draft), fileFormat (md|json|pdf|docx|csv|automate_draft), scope (blueprint|steps), stepIds[], targetId, blueprintVersion, contentHash, sensitivityAtExport, createdAt, createdBy`. Migration: `spec_markdown` to (process_document, md); `spec_json` to (blueprint_json, json); `spec_pdf`/`spec_docx`/`csv` to process_document with that format; `automate_flow_draft` to (automate_flow_draft, automate_draft). Policy `data.exports.allowedKinds` is null or an array of these kinds.
- **AuditEntry:** `actor.type` includes `server`; `details` keys registry `callId, connectionId, modelId, tool, entityIds[], evidenceRef`; action names registered in `x-actions`. **SelfAttestation** (Individual advisory review path; audit action `self_attested`; never sets `approved`): `{blueprintId, contentHash, attestedBy, at, statement (max 400)}`, owner role only. **ApprovalRecord:** `{recordId, blueprintId, rev, contentHash, reviewerId, decision (approved|rejected), at, kid, signature}`, carried in `auditEntry.details` when `action = approval_recorded`; the adapter verifies `signature` and recomputes `contentHash`. The schema publishes `x-virtualFields` (`step.derived.domains[]`) for the org-rule builder.
- **Connection:** `id`, `type`, `label`, `endpoint` (https; http only for loopback `local`), `serverKind` (`ollama|lmstudio|foundry_local|llamacpp|vllm|litellm|azure_openai|bedrock|vertex_openai|anthropic_compat|openai|openrouter|generic`), `authScheme` (`none|bearer|api_key_header|token_provider`), `credentialMode` (`user_supplied|integrated_oauth|org_vault|none`), `credentialRef` (nullable local reference, never the secret), `extraHeaders` (non-secret), `modelIdKind` (`model|deployment`), `contextWindowOverride`, `allowedModels[]`, `policyRef`. Policy `orgConnection` has the same shape without `credentialRef`. Schema file: `design/connection.schema.json`.
- **CapabilityReport** (keyed by `connectionId, modelKey, probeVersion, endpoint hash`; not stored on Connection): fields per `model-certification.md` plus `toolsInContent, thinkLeak, silentTruncation, toolsPlusSchemaOk, serverVersion, modelDigest`. Context size is probed per server kind. Never send `tools` and `response_format` together to open-weight servers.
- **Policy:** `schemaVersion`, `orgId`, `version`, `issuedAt`, `expiresAt`, `signature`, `settings{<key>:{state, value?}}`. Add `data.sensitivityRules[class].toolDataFlowCeiling` (`local|tenant|vendor_cloud|ai_cloud`, defaults per the engine) and `coach.aiMode` (`off|lite_only|full`, lockable, Team minimum; `off` means wizard only and no model traffic) with a per-mode allow list for rescue and second opinion. Environment profile gains `preferredToolIds`.
- **ToolCatalogEntry:** the 8 contract fields plus the 12 optional extension fields already in `$defs/toolCatalogEntry`; `environment.customTools[]` accepts the same optional fields (defaults `dataFlow = vendor_cloud`, `unattendedSupport = no`); `capabilities` use the 36-tag enum.
- **Sync envelope:** `{id, tenantId, rev, baseRev, status, sensitivity, schemaVersion, contentHash, size, clientTs, deviceId, enc{mode, alg, kekVersion}}`, `If-Match: <rev>`; `rev` exists only in the envelope and `Blueprint.sync`. Versioned optimistic concurrency with a client-side three-way merge by step.
- **Hashes:** `contentHash` = SHA-256 hex of the RFC 8785 canonical Blueprint without `auditLog, status, updatedAt, version, sync, etag, exports`, the root `engine`, every property marked `x-derived` (recommendation, derived roi and triage fields, per-entity engine meta) and the run-result fields of `tests[]` (`lastRunAt`, `lastRunId`, `lastRunDetail` and the run outcome), published once as `x-hashes.contentHash.exclude` in the Blueprint schema and generated from the `x-derived` markers, so approval survives exports, merges and test runs; `etag` = client-local base64url hash without `etag` and `sync`; `exportRecord.contentHash` = SHA-256 of exported bytes; `engine.inputsHash` = SHA-256 of canonical engine inputs; `traceHash` = SHA-256 of canonical `ruleTrace`.
- **ROI:** constants are placeholders; the triage ROI gate (TR-3) is advisory until the owner calibrates it from design-partner data; constants are shown in the trace. Graduation (LLM-to-code) is deferred to v1.x: keep the rule spec, collect no content.

## 6. Certification and models
Labels: `certified`, `works`, `experimental`, `uncertified`. A label belongs to a fingerprint (model, server kind, server version, quantization). Models reached through a degraded compatibility layer (for example Claude via an OpenAI-compatible layer) cap at `works`. Deterministic metrics decide labels; any LLM judge is advisory only; zero S0 runs for any model exposed to approval-class tools. Experimental models may propose but get no approval-class or AutoMate action-starting tools (users use panel buttons). Adversarial suites never run on the production gateway account; use a separate funded OpenRouter account and local models, with written approval before any red-team traffic. The `restricted` default model floor allows an admin-approved local model to count as `works`, otherwise the wizard.

## 7. Launch scope
Launch: engine and blueprint, no-AI wizard, chat coach, five connection types (managed behind the flag), local models with a readiness check, signed policy with machine enrollment, thin-but-real admin portal (Policy, Models, Users and roles, Spend, Audit, Review queue), full backup/sync (restricted opt-in), AutoMate draft actions. **Cut to P2:** Intake queue, Templates, org-rule editor, multi-reviewer approval and review SLA (hidden until built), org key vault, CMK, in-transit scan, graduation. Approvals: records and one reviewer at Team; multi-reviewer at Enterprise. Sensitivity-rule editing is not available on Individual. Individual review path is advisory with a recorded self-attestation. Rescue ("rescue my failed automation") and second opinion are available on all tiers, gated per `coach.aiMode`; the cross-model check obeys `data.sensitivityRules`.
